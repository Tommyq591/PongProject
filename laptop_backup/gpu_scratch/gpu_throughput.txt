 WHY THE GPU HELPS SO LITTLE: GPU utilisation is ~16%. The network is tiny (batch 32,
 ~425k params) and updates happen every 4 decisions; time goes to emulator stepping, numpy
 replay sampling/stacking, Python overhead and per-update GPU syncs (float() of 5 metrics).
 Faster training would need code changes (e.g. vectorised envs, bigger batches) - not done.

-------------------------------------------------------------------------------------
5. RAM ESTIMATES BY REPLAY SIZE
-------------------------------------------------------------------------------------
 Replay costs 14,142 bytes per slot (two 84x84 uint8 frames + small fields).
 Observed: next_frames (np.zeros_like) is committed immediately; frames (np.zeros) fills
 lazily, so short runs understate the final size. Model fits all measured runs.
 Baseline process (no replay): CUDA 1.81 GiB, CPU 0.76 GiB.
 Checkpoint save (notebook's Trainer.save: torch.save of the whole replay into gzip) needs
 an extra ~3.9x the replay size TRANSIENTLY: measured 8.25 GiB peak vs 3.13 GiB steady at 100k.
 It took 8.0 s and produced a 24.8 MB checkpoint.pt.gz (+1.6 MB policy.pt).
